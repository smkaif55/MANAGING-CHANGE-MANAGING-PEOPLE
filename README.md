## 📌 Overview
This repository contains the presentation slides (`Managing_Change_Managing_People BY S M KAIF.pptx`) developed for our **Software Project Management** course under the guidance of **Ms. Ashrafia Esha (Lecturer)** at the **Department of Software Engineering, Daffodil International University (DIU)**.

Real-world software projects frequently fail due to unmanaged scope creep, uncontrolled late-stage requests, and misaligned human expectations. This presentation bridges **PMBOK® Guide (6th Edition) Chapter 4 (Project Integration Management)** and **Chapter 13 (Project Stakeholder Management)** to demonstrate how software teams govern change requests without compromising baselines, code quality, or delivery deadlines.

## 🗂️ Presentation Structure (12 Slides)

| Slide | Topic | Key Takeaways |
| :--- | :--- | :--- |
| **01** | **Title & Team Introduction** | Project overview and team roster (**Team LADS**). |
| **02** | **Presentation Roadmap** | Three-part framework connecting people, process, and practical integration. |
| **03** | **A Real Project Situation** | Handling a late-night client feature request (`11:42 PM` midway through Sprint 4). |
| **04** | **Academic Foundation** | Aligning PMBOK® Ch. 4 & Ch. 13 (*Process without people = Resistance; People without process = Project failure*). |
| **05** | **Stakeholder Identification** | Mapping roles in a university software system (Team Leader, Sponsor, Users, Client, Developers). |
| **06** | **Stakeholder Analysis** | Prioritizing communication using the **Power/Interest Grid**. |
| **07** | **Engagement Matrix** | Moving stakeholders across the spectrum: *Unaware → Resistant → Neutral → Supportive → Leading*. |
| **08** | **Integrated Change Control** | The formal 5-step process (*Submit Request → Evaluate Impact → CCB Decides → Implement → Update & Inform*). |
| **09** | **Impact Assessment** | Evaluating ripple effects across Scope, Schedule, Cost, Quality, and Risk. |
| **10** | **Practical Case Study** | **DIU System v2.0:** Resolving a Sprint 4 biometric attendance feature request via Phase 2 deferral. |
| **11** | **Key Lessons** | Core takeaways: *Listen First, Assess Before Approving, Communicate Every Decision*. |
| **12** | **Concluding Remarks** | Summary and Q&A. |
